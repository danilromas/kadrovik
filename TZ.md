## 1. Назначение документа

Данное ТЗ фиксирует **объём работ**, необходимый для приведения текущей реализации платформы «КАДРОВИК» в соответствие с целевым описанием из `documentation.md`: job-платформа + HRM/ATS, production-ready frontend.

Документ используется для:
- планирования спринтов и оценки трудозатрат;
- контроля полноты реализации;
- согласования приоритетов между MVP и последующими итерациями.

## 3. Текущее состояние (краткая аналитика)

### 3.1. Реализовано частично или на базовом уровне

- Публичные страницы: главная, вакансии (список + деталь), компании (список + деталь), каталог резюме (`/resumes`).
- Авторизация: логин/регистрация/logout, mock JWT в Zustand, защищённые маршруты, раздельные layout для кандидата/работодателя/админа.
- Кандидат: дашборд, профиль (упрощённо), список резюме, отклики, избранное, чат, уведомления, настройки.
- Работодатель: дашборд, профиль, сообщения, уведомления, настройки (узкий набор маршрутов в `App.tsx`).
- Админ: только дашборд-обзор; пункты меню админки без соответствующих страниц.
- Моки: пользователи, вакансии, компании, резюме, отклики, чат, уведомления, аналитика (частично).

### 3.2. Системные расхождения с доком

- Заявленная **feature-based** структура (`entities`, `widgets`, отдельные `features/vacancies`, `organizations`, `pipeline`, `analytics`) в коде **не соблюдена** (часть в `pages/`, без выделенных сущностей).
- Ряд зависимостей из дока **установлен, но не используется** в `src`: `react-hook-form`, `zod`, `@tanstack/react-query` (кроме провайдера), `recharts`, `@dnd-kit/*`, `sonner`, `vaul`.
- Маршруты, на которые ведут ссылки в **DashboardLayout / AdminLayout / футере**, **отсутствуют** в `App.tsx` (404).

---

## 4. Целевое состояние

По завершении работ платформа должна **покрывать функциональные и архитектурные требования** из `documentation.md` в объёме, согласованном с заказчиком по этапам (раздел 7). Минимальный критерий успеха этапа **MVP+**: отсутствие «битых» ссылок в основной навигации, ключевые сценарии кандидата и работодателя доступны из UI, админ-разделы либо реализованы, либо скрыты до готовности.

## 8. Критерии приёмки (общие)

1. Каждый пункт раздела **5**, включённый в выбранный этап, имеет **проверяемый результат** (экран, сценарий, отсутствие ошибки в консоли).
2. Новые маршруты отражены в **`App.tsx`** (или вынесенном роутере) и доступны из UI без 404.
3. Обновлённая структура каталогов не противоречит разделу **5.1** либо в ТЗ зафиксировано осознанное отклонение с обновлением `documentation.md`.
4. После этапа форм (**5.13**) минимум: логин, регистрация, создание резюме, создание вакансии — проходят валидацию Zod.
